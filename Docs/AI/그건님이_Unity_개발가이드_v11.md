# 《그건 님이!!!》 Unity 개발 가이드 · v11

2026-11-18 · 웹 동작 기준 `zoom-speed61` · Unity 기준 `6000.3.28f1`

v11에는 최신 웹 프로토타입, 웹 렌더러에서 추출한 PNG 리소스, Unity 씬과 패키지 설정이 들어 있다. 웹판에서 게임을 실행하고, Unity 프로젝트의 씬 배치를 출발점으로 삼아 그래픽과 게임 규칙을 적용한다. [공개 웹판 플레이](https://goblin-getaway-crew.vercel.app/)

## 처음 열기

1. ZIP을 풀고 `Assets`, `Packages`, `ProjectSettings`가 있는 폴더를 Unity Hub에 추가한다. Unity `6000.3.28f1`로 연다.
2. `Assets/Scenes/Scene.unity`의 복제본에서 적용한다. `Cart`, `PLAYER`, 두 `Horse`, `Cannon`, `Bomb_Store`, `Bomb_Ready`, `Bomb_Reload`, `Prince`, `Queen`을 배치 참고점으로 사용한다. `Queen`은 공주 자리다. `Assets/Scenes/YMH/YMH_Scene.unity`에도 참고 배치가 있다.
3. ZIP 루트의 [리소스 읽기](../../v11-graphics/리소스_읽기.md)와 [리소스 목록](../../v11-graphics/리소스_목록.csv)을 열고 가져올 파일을 고른다. PNG 하위 폴더 구조를 유지해 `Assets/WebGraphics/`로 복사한다.
4. 웹판의 **테스트 모드**에서 포탄 공급·장전·발사, 도로 장애물, 투석기 경고를 반복한다. **환경설정 → 협동 플레이 → 한 화면 협동**에서 각자 작업대를 점유해 분할 시야와 아이콘 투영을 비교한다.

동봉 Unity 프로젝트는 씬 배치와 설정을 제공한다. 게임플레이 C#, 프리팹 연결, Unity 네트워크 통합은 이식 작업이다. `Packages/manifest.json`에는 URP 17.3.0, 2D Sprite, Input System 1.20.1, uGUI 2.0.0, Netcode for GameObjects 2.14.0, Test Framework 1.6.0이 선언돼 있다. 실제 동작은 동봉 웹판에서 재현할 수 있다.

### Sprite 가져오기

1. Unity Inspector에서 `Texture Type`을 `Sprite (2D and UI)`로 선택한다. PNG 한 장에 이미지 하나면 `Sprite Mode`는 `Single`, 여러 프레임이면 `Multiple`로 둔다. 투명 PNG는 원본 알파를 읽고 `Alpha Is Transparency`를 켠다.
2. 첫 비교에서는 `sRGB` 활성화, `Filter Mode`는 `Bilinear`, `Mesh Type`은 `Full Rect`, 압축은 `None`을 기준으로 한다. `Max Size`를 원본 시트 전체 크기 이상으로 맞추고, 투명 가장자리와 시트 크기를 유지한 상태에서 검증한다. Atlas나 플랫폼 압축은 색과 알파를 대조한 뒤 적용한다. [Unity Sprite 가져오기 설정](https://docs.unity3d.com/6000.3/Documentation/Manual/texture-type-sprite.html)
3. 프레임 시트는 Sprite Editor에서 메타데이터에 적힌 셀 크기·간격·순서로 자른다. 프레임에 여백이 있어도 크기와 피벗을 동일한 기준으로 둬서 달리기나 이펙트 중심이 흔들리지 않게 한다. Unity Inspector에서 `Apply`를 누르고 펼쳐진 서브 스프라이트 순서를 확인한다. [Unity Sprite Editor 슬라이싱](https://docs.unity3d.com/6000.3/Documentation/Manual/sprite/sprite-editor/automatic-slicing.html)
4. 좌표 환산 예시는 **웹 월드 100단위 = Unity 1단위**다. 월드 1단위당 2픽셀로 추출한 PNG에 `Pixels Per Unit = 200`, 1픽셀의 배경 레이어에는 `100`을 적용한다. 파일별 추출 배율이나 권장 PPU가 제공되면 그 값을 우선한다. 웹 렌더러의 스케일이 이미 구워진 이미지에는 스케일을 한 번만 적용한다. UI 크기는 Canvas의 `RectTransform`에서 정한다.
5. 메타데이터에 Unity용 정규화 피벗이 있으면 그 값을 바로 적용한다. PNG 왼쪽 위 기준 프레임이 `(x, y, w, h)`일 때 왼쪽 아래 기준 SpriteRect의 Y는 `이미지높이 − y − h`다. 같은 프레임 안의 로컬 앵커가 왼쪽 위 기준 `(ax, ay)`라면 Unity 피벗은 `(ax / w, 1 − ay / h)`다.

### 씬에 붙이기

- 웹은 왼쪽으로 주행하고 아래쪽이 +Y다. 월드나 마차의 기준점 `(ox, oy)`를 정한 뒤, 웹 좌표 `(x, y)`를 Unity의 `((x − ox) / 100, (oy − y) / 100)`로 변환한다. 갑판과 지하층의 위치는 마차의 로컬 좌표로 두고, 도로와 착탄 효과는 월드 상태에서 투영한다.
- 마차 루트 아래에 갑판·지하층을 두고, 포신·바퀴·말·왕자와 공주·작업대는 상태별로 교체할 수 있게 분리한다. `Carriage/wagon-deck.png`와 `Carriage/wagon-cellar.png`는 공통 앵커 `(527, 0)`으로 맞춘다. 예를 들어 장전대 `(622, −39)`의 Unity 로컬 위치는 `(0.95, 0.39)`다. 지하층 카메라에는 어두운 외부 배경을 별도로 두고 지하층 몸체의 투명 영역을 채운다.
- 갑판 몸체에는 깃발과 좌석 바탕이 들어 있다. 말·바퀴·포신·계단·작업대·탑승자는 별도 이미지로 얹는다. 포신은 발사 방향으로 회전하고 바퀴가 이탈하면 해당 월드 바퀴로 교체한다. 졸개 이동과 작업대 반경은 `sim.mjs`의 로컬 좌표에서 가져온다. 왕자와 공주의 단독 착석 스프라이트는 원본의 0.83배를 적용한다.
- 화면 합성 순서는 **배경과 윗길가 → 도로 장애물과 착탄 흔적 → 추격대·빠진 바퀴 → 1층 마차·탑승자 → 아랫길가 → 투사체·먼지·투석기 그림자 → UI**를 기준으로 잡는다. 지하층을 보는 카메라는 지하층 그래픽과 해당 층의 캐릭터·작업만 표시한다. 2인 분할에서는 층과 작업 시야를 카메라별로 적용한다.
- 반복 배경은 레이어별 시트 너비를 반복 주기로 사용하고, `s.road`에 대응하는 하나의 누적 도로 오프셋을 공유한다. 도로와 장애물의 상대 위치를 맞춘 뒤 질감·숲·길가를 얹는다. 배경 시안 전체를 타일처럼 반복하면 실제 도로 경계와 나무 판정 위치를 맞추기 어렵다.
- 걷기·달리기 시트는 메타데이터의 순서로 `Loop Time`을 적용한다. Units의 12프레임 시트는 4열 × 3행의 왼쪽 위부터 행 순서로 읽는다. 말·추격병 시트의 기본 재생 속도에는 최신 **2배** 보폭이 이미 반영돼 있다. 메타데이터의 재생 시간이나 FPS를 기준으로 지침 0.52배, 놀람 1.4배, 폭주 2.05배를 마차 말의 재생 속도에 적용한다. 착탄·먼지·반동 프레임은 이벤트 기준으로 한 번 재생한다.
- 포탄·대포 이펙트는 +X를 기준으로 방향을 맞추고, 포구·착탄점 및 도로 오프셋을 따라가게 한다. 바위의 가시 반경, 연기 크기와 먼지 프레임은 연출용이다. 피격과 장애물 충돌은 `sim.mjs`의 타원·거리 판정으로 계산한다.
- uGUI는 `Scale With Screen Size`와 기준 해상도 `1920 × 1080`으로 시작한다. 플레이어별 화면 사각형 안에서 행동·이모티콘·이탈 버튼과 작업 안내를 배치한다. 뜨는 알림은 `Raycast Target`을 꺼서 터치 입력이 아래 버튼에 전달되게 한다. `UI/catapult_warning.png`는 그림자의 중심을 화면으로 투영하고 작업 안내보다 앞에 띄운다. 분할 화면에서는 플레이어별 Canvas 또는 `RectMask2D` 영역으로 잘라낸다. 모바일 안전 영역과 2인 분할에서 버튼·알림이 각자의 영역 안에 드는지 확인한다. [uGUI Canvas Scaler](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/script-CanvasScaler.html)

PNG는 Canvas와 HUD의 외형을 옮기기 위한 자료다. 캐릭터 상태 변화, 충격 오프셋, 상처·점화·착탄 시드, 배경 반복, UI 안전 영역과 배치는 소스에서 상태에 따라 계산한다. 메뉴 글자와 작업 안내는 Unity 텍스트로 구성하고, 운영체제 글리프를 쓰는 이모티콘은 동일한 기능과 글자 대체를 확인한다. 발표용 BGM 두 곡의 MP3·WAV와 편곡·렌더 소스는 `goblin-getaway/handoff/music/`에 있다. 게임 효과음, 울음과 착탄음은 `public/game.mjs`의 Web Audio 생성 코드를 기준으로 Unity에서 구현한다.

| 장전·포격 | 장전 성공·실패 모두 적재탄 한 발을 소비하고 작업대를 해제한다. 성공 후 포수석에서 점화하면 **2.5초** 동안 조준을 이어간 뒤 발사한다. 포탄은 초당 1,750 웹 단위로 직진 관통하고 착탄점 오른쪽에 충격파가 생긴다. 흔적·연기는 도로 오프셋을 따라간다. |

### 작업대 배치

아래 좌표는 원본 웹 월드 X와 마차 기준 로컬 Y다. 수치 `r`은 작업 진입 반경이다. 도로의 Y는 마차 중심 Y에 로컬 Y를 더해 구한다.

| 층 | 작업대 | 웹 좌표 및 반경 |
| --- | --- | --- |
| 1층 | 마부석, 포수석 | `(385, 0, 26)`, `(658, 3, 26)` |
| 1층 | 장전대, 포신 청소대, 적재함 | `(622, −39, 21)`, `(674, −41, 20)`, `(674, 62, 19)` |
| 지하층 | 포탄 더미, 음식 제작대, 예비 바퀴 보관함 | `(665, 0, 23)`, `(383, −21, 24)`, `(528, −62, 24)` |
| 공용 | 계단 | `(502, 65, 18)` |

1층과 지하층에서 계단을 한 번 밟아 이동한 뒤 작업 원 밖으로 나와야 다시 탈 수 있다. 바퀴 수리는 지하 보관함에서 예비 바퀴를 가져와 해당 모서리에서 **바퀴 끼우기 → 차축 핀 고정** 순으로 진행한다. 점유자는 한 작업대당 한 명이며 사람이 봇보다 우선한다. 이동·조준·행동의 소유자는 입력에서 판별하고, 렌더러는 서버나 로컬 시뮬레이션이 확정한 점유 상태를 읽는다.

스테이지 목표는 현재 각 1,000m다. 캐릭터·적·포탄의 움직임과 상태는 30Hz 틱에서 계산하고 카메라와 애니메이션은 그 상태를 읽는다. 돌봄은 **안아 들기 → 이동으로 달래기 → 자기 좌석에 앉히기** 흐름을 따른다. 지루함, 울음 비중과 타이밍 판정 폭, 마왕 보고와 협동 정비의 상세 규칙은 기존 [v10 상세 규칙](그건님이_Unity_개발가이드_v10.md)과 현행 소스를 같이 본다. 두 문서의 수치가 다를 때 위 v11 표와 동봉 웹 소스를 적용한다.

## 적용 후 검증 순서

1. 마차·말·졸개·왕자와 공주의 축척을 맞춰 한 화면을 구성한다. 달리는 말과 투사체의 방향, 프레임 전환 시 피벗, 아랫길가의 가림 순서를 대조한다.
2. 전방 장애물의 예고와 실제 진입 차선, 배경과 장애물의 같은 속도, 투석기 노란색·빨간색 전환을 확인한다. 회피할 때 느낌표가 사라지고 착탄 판정과 표시가 일치하는지 본다.
3. 포신 청소 12회, 장전 성공·실패, 발사, 반동과 포탄 붙잡기를 확인한다. 발사 후 포수 시야는 2초 유지되며 복귀 0.5초가 끝날 때 자동 이탈한다.
4. 로컬 1인, 한 화면 2인, 온라인 2인과 4인 순서로 늘린다. 1층과 지하층이 동시에 보일 때 각 화면의 작업 말풍선·착탄 경고·조작부가 맞는지 확인한다. 같은 방에서 적재함에 포탄을 추가하면 모두 같은 재고를 보는지 검증한다.
5. 실제 목표 해상도에서 명암·알파와 조작 범위를 확인한 뒤 압축·Atlas를 적용한다. 추가 전후 빌드에서 느린 프레임, 메모리, 경계에 번지는 색을 비교한다.

## 동봉 웹판 실행

Node.js 22.13 이상과 npm을 설치한다. ZIP 안 `goblin-getaway` 폴더에서 실행한다.

```sh
npm ci --include=dev
node ./node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3000
```

`http://127.0.0.1:3000`에서 로컬 1인·한 화면 2인과 테스트 모드를 실행할 수 있다. 테스트 모드는 목적지에 도달해도 계속 달리고 내구도 최소치 1을 유지한다. 종료하려면 **환경설정 → 테스트 종료**를 누른다. 배포와 같은 경로로 빌드를 확인하려면 `node ./node_modules/next/dist/bin/next build`를 실행한다. ZIP 루트의 `node --test tools/playtest/playtest.test.mjs`로 웹 회귀 테스트를 실행한다.

온라인 방을 시험하려면 개발용 Turso 데이터베이스와 서버 환경변수 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`을 준비한다. DB 마이그레이션은 `goblin-getaway`에서 `node ./scripts/migrate-rooms-vercel.mjs`로 적용한다. 방을 시작한 뒤 독립된 브라우저 프로필로 참가한다.
