## 데이터와 좌표

- 규칙은 **30Hz** 고정 틱에서 계산한다. 주행 거리(m), 갑판·지하층 로컬 좌표, 화면 투영을 분리한다. 웹판은 왼쪽으로 전진하고 Y가 아래로 증가한다. Unity Transform으로 변환할 때 Y 반전을 한곳에서 적용한다.
- 웹에서 1m 주행은 도로 위치 4단위 이동이다. 도로 무늬·숲·장애물은 같은 누적 주행 값에서 위치를 구한다. 착탄·연기는 도로상 위치에 고정해 배경과 함께 이동시킨다.
- 이동축·조준축·행동 시작과 해제·이탈·소통을 명령으로 보낸다. 카메라와 HUD는 상태를 읽고 소리와 충격은 이벤트 ID를 기준으로 한 번 재생한다.
- 챕터·스테이지·웨이브, 적 특성, 작업대·업그레이드는 ScriptableObject로 옮기고 재고·거리·투표는 판마다 독립적인 런타임 상태로 관리한다. 같은 시드와 틱 입력으로 웹판과 Unity판을 비교한다.
- 모바일 가로형 Canvas 기준 해상도는 1920×1080이다. 실제 기기의 안전 영역과 터치 범위를 본다. 온라인 개인 카메라와 로컬 2인 분할 카메라의 HUD 투영을 각각 검증한다.

## 층과 작업대

| 위치 | 배치와 동작 |
| --- | --- |
| 1층 | 맨 왼쪽 마부석 한 개, 왕자·공주 좌석, 뒤쪽 포수석·장전대, **5시 구석** 포탄 적재칸 |
| 지하층 | **3시** 포탄 더미, **9시 반** 음식 제작대, **12시** 바퀴 보관함, 고장 난 바퀴 모서리의 수리점. 어두운 실내에서 외부 시야를 차단한다. |
| 양쪽 6시 반 | 같은 마차 좌표의 계단. 한 번 건너면 바깥으로 나갔다가 다시 밟아 층을 바꾼다. 포탄·간식을 들거나 아이를 안고 계단을 이용할 수 있다. |

작업 범위에 들어가면 한 명이 점유한다. 사람은 봇보다 우선하고, 이탈하면 이동과 시야가 복귀한다. 작업대 바깥을 밟아야 다시 들어간다. 바퀴 수리는 지하 보관함에서 예비 바퀴를 들고 와 **바퀴 끼우기 → 차축 핀 고정**의 타이밍 작업을 한다. 웹의 기본 이동 165, 예비 바퀴 운반 110, 포탄 운반 50이며 포탄 운반 장구는 포탄 소지 속도에 적용한다. 바퀴 이탈 중 목표 주행 속도는 57%다.

포신이 비어 있고 적재탄이 있을 때 장전하면 한 발을 소비한다. 성공 시 장전하고 실패 시 한 발을 잃는다. 두 결과 모두 장전대에서 자동 이탈하며, 결과 안내를 띄운 채 이동·일반 시야로 복귀한다. 다음 장전은 작업 원 밖으로 한 걸음 나갔다가 다시 들어가 시작한다.

구현 파일은 `public/sim.mjs`, `public/workstation.mjs`, `public/scene.mjs`다.

## 입력·HUD·소통

- 터치 화면 왼쪽 절반에서 누른 곳을 중심으로 가상 조이스틱을 띄운다. 평소 이동, 마부석·포수석 점유 중 조준, 장전 같은 다른 점유 작업 중에는 대기다. 화면 오른쪽 행동 버튼은 현재 작업에 따라 탭·연타·홀드로 동작한다. 점유 중 화면에 이탈 버튼을 표시한다.
- P1은 WASD·Space·Q, P2는 방향키·Enter·오른쪽 Shift, 게임패드는 왼쪽 스틱·A 또는 R2·B를 쓴다. PC에서 Esc로 작업대를 이탈한다. 로컬 2인 모두 작업 중이면 P1부터 이탈한다.
- **작업 말풍선**은 이모티콘 팀 알림과 같은 스타일이다. “왼쪽 스틱으로 착탄점을 맞추세요”처럼 지금 할 행동을 각자의 캐릭터 위에 띄운다. 포수는 조준률과 심지 시간, 요리·달래기·말 상태는 진행도를 표시한다. 캐릭터가 조준 화면 밖에 있으면 같은 플레이어 영역 안쪽에 말풍선을 놓는다. 타이밍 바늘과 성공 구간은 충격이 적용되기 전 카메라로 캐릭터 위치를 투영해 제자리를 유지한다.
- 상단 중앙에는 마차 아이콘이 있는 거리 진행 바, 남은 거리와 현재 웨이브가 표시된다. 층수와 다음 웨이브 예고는 기본 HUD 구성에서 제외한다.
- 이모티콘 원형 버튼은 행동 버튼과 **같은 지름·높이**로 그 바로 왼쪽 **9시 방향**에 둔다. 목록은 버튼 위쪽에서 각 플레이어 영역의 너비에 맞춰 열리고, 화면이 낮으면 스크롤된다. 숫자키 1–7은 포탄·장전·바퀴 수리·마차 조작·아이 돌봄 요청, 좋아요와 놀람을 보낸다. 사용자 캐릭터 옆에 아이콘을, 팀원 모두의 상단에 메시지를 띄운다. 한 화면 2인에서 P2 목록이 열리면 숫자키는 P2에 적용한다.
- 일반 주행과 마부석은 말·마차·탑승원 묶음의 중심을 화면 너비 **55%**에 잡아 화면 왼쪽에 앞길을 더 보여준다. 마부석은 일반 주행보다 가로·세로에 각각 **15% 더 많은 월드 범위**를 담는다. 분할 화면은 각 영역을 기준으로 이 구도를 계산한다.
- 환경설정은 88×88px, 작전 시작은 높이 84px 기준이다. 좁은 화면에서 진행 바·팀 알림과 터치 영역의 겹침을 확인한다.

구현 파일은 `public/controls.mjs`, `public/game.mjs`, `public/workstation.mjs`, `public/emotes.mjs`, `app/page.tsx`, `app/globals.css`다.

## 포수·마부·추격대

- 더미 17발, 적재 1발, 장전 1발로 시작한다. 포수의 왼쪽 스틱으로 조준점을 상하좌우로 옮긴다. 점화 후 **2.5초** 동안 계속 조준한 뒤 자동 발사한다. 웹 좌표에서 착탄점 조준 범위는 X 866–1,080, 마차 기준 Y 최대 ±154다. 포신 흔들림은 이전 대비 **10% 감소**했다. 조준률은 32–98% 범위에서 출렁이며 낮을수록 표시된 착탄 타원이 넓어진다. 반지름은 최대 X 50, Y 43이고, 서버가 시드 기반으로 그 안의 실제 착탄점을 고른다.
- 포탄은 웹 좌표 초당 **1,750**, 기본 반지름 **14**로 실제 착탄점까지 직진한다. 틱 사이 이동 선분이 만나는 적을 모두 관통한다. 착탄 뒤 화면 오른쪽(+X)으로 충격파가 퍼진다. 기본 길이 200, 최대 반폭 87이며 포신 강화에 따라 길이 최대 235, 반폭 최대 107이다. 폭은 위치에 따라 달라지고 끝에서 좁아진다. 발사와 착탄으로 같은 적을 중복 집계하지 않는다. 착탄 흔적과 연기는 도로 위치에 고정해 **3초** 동안 표시한다.
- 반동은 마차 전체와 포탄 운반자에게 전달된다. 운반 중 놓칠 위기에는 **1.6초** 안에 타이밍을 맞춰 붙잡는다. 카메라, 먼지, 소리는 충격 이벤트에 반응한다.
- 마부석은 가로·세로 시야 범위가 일반 주행 대비 15% 넓다. 말의 엉덩이를 조준해 연타하면 가속과 조향이 쌓인다. **오른말은 화면 위, 왼말은 화면 아래**로 튼다. 허리·목·머리에 맞으면 약 3초간 해당 말이 놀라 조작에 반응하지 않는다.
- 한 말의 엉덩이에 타격 **8회**가 누적되면 그쪽으로 **1.2초 폭주**한다. 웹 기준 횡이동은 초당 176단위고 기본 주행 속도의 18%가 추가된다. 이후 **4초 지침**에는 그 말의 가속이 사라지고 목표 주행 속도에 0.78배를 적용한다. 지침 동안 상처가 회복되고 정상으로 돌아온다. 폭주는 한 번에 한 마리에서 발동한다. HUD에 타격 수·폭주·회복 상태를 표시한다.
- 추격대는 화면 오른쪽 바깥에서 접근한다. 일격 후 0.8초 후퇴하고 약 1.4초간 접근 속도를 40%로 낮춘 뒤 재공격한다. 기병의 말은 마차 말과 같은 그리기 배율인 1.58을 사용한다. 기병 말 몸통 판정을 외형에 맞추고 공격 지점은 창 길이에 맞춘다.
- 통나무·바위·사슴은 화면 왼쪽에서 위·아래 두 바깥 차선(Y 82, 282) 중 한 곳에 나온다. 일반 주행과 마부석에는 **4초 전 빨간 느낌표**가 예정 차선 높이에 뜬다. 첫 예고는 주행 42m부터, 이후 예고 기본 간격은 **125–150m**다. 예정 위치를 유지하고 생성 뒤에는 배경과 함께 같은 거리만큼 움직인다. 충돌하면 종류에 맞는 피해와 감속이 생긴다.
- **빠진 바퀴**는 마차 뒤로 굴러가고, 경로에 걸린 기병을 날려 보낸다. 길가 나무·통나무·바위에 부딪히면 방향이 바뀌고 화면 뒤편으로 멀어지면 제거한다. 틱 사이 바퀴와 기병의 상대 이동을 판정한다. 지하에서 예비 바퀴로 수리하는 흐름은 굴러가는 바퀴와 독립적이다.
- 투석기는 기본 시작 6초 후 첫 바위를 예고하고 이후 약 12–13초마다 던진다. 그림자가 접근하고 발사 1.1초에 착탄 표시를 고정한 뒤 4.8초에 떨어진다. 가속으로 착탄 지점을 지나가거나 반대쪽으로 조향해 피한다. 경고 표시 지름은 2배이며 실제 판정 타원 반지름은 35×24다. 도로 장애물과 타이밍이 겹치면 발생을 미루거나 투석기 방향을 바꿔 공통으로 피할 차선을 확보한다. 착탄 때 큰 바위, 지면 흔들림과 먼지를 보여준다.

구현 파일은 `public/sim.mjs`, `public/horse-targets.mjs`, `public/road-obstacles.mjs`, `public/scene.mjs`다.

## 왕자·공주 돌봄

- 아이별 관심과 배고픔을 계산한다. 관심 20 이하에서 자리를 뜨고 통로를 막을 수 있다. 가까이에서 상태가 나타난다. 돌아다니는 동안 적재탄 버리기, 대포 발사, 말 재촉을 할 수 있다.
- 앉은 아이는 대포 반동 25%, 투석기 명중 52%, 장애물 충돌 34%의 기본 확률로 떨어진다. 완충 강화는 이 확률을 낮춘다. 낙상 시 85% 확률로 놀라 운다.
- **안아 올리기 → 안고 걸어서 달래기 → 1층 자기 좌석에서 행동해 앉히기** 순서다. 달래기는 실제 이동거리 312.5단위를 누적해 완료한다. 멈춰 있거나 벽에 막히면 진행도를 유지한다. 재착석하면 관심이 차고 약 7초간 자리에 머문다.
- 놀라 우는 아이를 안을 때 **30% 확률**로 지루함을 예약한다. 달래기가 약 3분의 1에 도달할 때 갑판에 있으면 “지루해요”를 띄우고 진행을 멈춘다. 지루해진 위치에서 82단위 이상 떨어진 갑판 앞뒤 구역에 닿거나 계단으로 지하층에 가면 쌓아둔 진행도부터 다시 달랜다. 지하층에서 그 기준에 도달하면 중단 없이 이어진다.
- 지하 9시 반 음식 제작대에서 행동을 홀드한다. 물리적인 충격을 받으면 쌓인 진행도가 줄어든다. 1층 자기 좌석에 앉은 아이에게 간식을 먹이면 배고픔이 55 내려간다. 배고픔이 70 이상인 울음과 놀라서 우는 상태는 별도로 계산한다.

| 우는 아이 수 | 졸개 이동 속도 | 요리 진행 속도 | 타이밍 성공 구간 폭 |
| --- | ---: | ---: | ---: |
| 0명 | 100% | 100% | 100% |
| 1명 | 90% | 85% | 80% |
| 2명 | 75% | 65% | 60% |

이동 배율은 운반에도 적용돼 걸으며 달래는 시간에 반영된다. 요리의 실제 홀드 시간은 충격이 없을 때 순서대로 3.00초, 3.53초, 4.63초다. 성공 구간 배율은 강화 카드가 반영된 폭에 적용하고 바늘은 일정하게 회전한다. 서버 저장은 소수점 요리 진행도를 보존한다.

- 작업 성공과 층 이동, 지루함 예약·해제는 권한을 가진 시뮬레이션에서 처리한다. 온라인 스냅샷에는 아이와 운반자의 층, 달래기 진행, 장전 재진입 상태와 장애물 예정 차선을 포함한다.

구현 파일은 `public/sim.mjs`, `public/workstation.mjs`, `public/scene.mjs`, `public/game.mjs`다.

## 스테이지·정비

- 현재 1챕터 3스테이지, 각 목표 **1,000m**다. 웨이브 시간(초)은 스테이지 1 `4/16/28/40/52`, 스테이지 2 `4/15/26/37/48/59`, 스테이지 3 `3/13/23/33/43/53/63`이다. 기병·정찰병·근위병이 편성된다. 거리를 매 틱 누적하고 목적지 도달 시 클리어한다. 마지막 웨이브를 모든 판에서 보이게 하려면 가능한 강화·가속을 포함한 최단 완주 시간보다 웨이브 시각을 앞당긴다.
- 스테이지 종료 때 아이별 착석률 60%, 평균 관심 40%를 점수화하고 울음 비중에 따라 최대 4점씩 감점한다. 마왕에게 돌봄·마차 피해·보급 중 한 항목을 보고한 뒤 AP로 수리·업그레이드 카드를 구매한다. 비용은 3–6 AP, 같은 카드에 사람 과반수인 1·2·3·4인 기준 1·2·2·3표가 필요하다. 과반이 되면 AP를 한 번 차감하고 표를 초기화한다.
- 다음 스테이지에는 내구도·이탈 바퀴·업그레이드·AP가 이어지고 새 웨이브·재고·아이 상태를 시작한다. 마지막에는 평가를 표시하고 챕터를 완료한다.

구현 파일은 `public/campaign.mjs`, `public/sim.mjs`, `public/intermission.mjs`다.

## 무한 테스트 모드

로컬 1인과 한 화면 협동의 시작 대기 화면에서 **작전 시작** 왼쪽의 **테스트 모드**를 누른다. 목적지를 지나도 주행을 이어가고, 피해가 누적돼도 내구도는 최소 1을 유지한다. 스테이지 웨이브가 반복되고 지하 포탄 더미가 비면 보충된다. 웨이브 생성 시 오래된 적을 정리하고, 첫 일격을 가한 추격대는 14초 후 퇴장한다. HUD는 누적 주행 거리와 웨이브 수를 표시한다. **환경설정 → 테스트 종료**를 누르면 시작 대기로 돌아온다.

Unity판에서도 테스트·일반 모드가 같은 작업과 충격 판정을 사용하게 한다. 구현 파일은 `public/sim.mjs`, `public/game.mjs`, `app/page.tsx`다.

## 협동과 온라인

최대 네 자리, 3자리 방번호, 비어 있는 자리는 봇이 맡는다. 서버는 점유·재고·피격·아이 운반·투표를 확정하며 진행 중 합류와 이탈 시 캐릭터 상태를 넘긴다. 방장이 떠나면 남은 참가자에게 권한이 넘어간다. 웹 서버는 `app/api/room/route.js`에서 같은 시뮬레이션을 실행하고 클라이언트는 폴링 스냅샷과 예측으로 화면을 갱신한다. Vercel은 Turso, 이전 Sites 배포는 D1 어댑터를 사용한다.

Unity에서 NGO를 선택하면 명령과 상태 스냅샷을 교환하는 계층부터 만든다. 브라우저 두 개로 연결과 재연결을 검증한 뒤 네 자리, 봇 인계와 동시 투표를 확인한다. 기존 웹 방과 연결하려면 웹 HTTP 메시지 규칙과 배포 출처를 맞춘다. DB 자격증명은 서버 환경에 둔다.

## 동봉된 웹판 로컬 실행

Node.js 22.13 이상을 사용한다. ZIP 안 `goblin-getaway` 폴더에서 실행한다.

```sh
npm ci --include=dev
node ./node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3000
```

`http://127.0.0.1:3000`에서 1인과 한 화면 2인을 시험한다. 온라인 방은 개발용 Turso DB와 서버 환경의 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`이 필요하다. 변수를 설정한 후 `node ./scripts/migrate-rooms-vercel.mjs`를 한 번 실행한다. Vercel과 같은 진입점으로 빌드하려면 `node ./node_modules/next/dist/bin/next build`를 실행한다. ZIP 루트에서 `node --test tools/playtest/playtest.test.mjs`로 웹 회귀 테스트를 실행할 수 있다.

ZIP에는 Unity 씬과 설정, 웹 소스, 기획과 상세 명세, BGM 두 곡의 MP3·WAV·렌더 소스가 들어 있다. Unity Library와 웹 의존성은 각 환경에서 복원한다.
