# 《그건 님이!!!》 Unity 개발 가이드 · v8

2026-11-18 · Unity 프로젝트 기준 `MJ` / `444eff8`  
v8은 현재 Unity 작업본과 공개 웹판의 구현 규칙을 담은 인수인계 버전이다. 공개판은 [그건 님이!!!](https://goblin-getaway-crew.vercel.app/)에서 플레이할 수 있다.

## 처음 열기

1. ZIP을 풀고 `Assets`, `Packages`, `ProjectSettings`가 함께 있는 폴더를 Unity Hub에 추가한다. **Unity 6000.3.28f1**로 열어 패키지를 복원한다.
2. 빌드 목록의 `Assets/Scenes/Scene.unity`를 열어 직교 카메라와 마차 배치를 확인한다. `Assets/Scenes/YMH/YMH_Scene.unity`는 별도의 배치 참고 씬이다. 구현은 메인 씬 복제본에서 시작하고 첫 검증이 끝난 뒤 시작 씬을 연결한다.
3. 웹판에서 1인 연습으로 작전을 시작한다. 계단으로 내려가 포탄을 꺼낸 뒤 1층에서 적재한다. 장전·점화·반동과 2인 화면 전환을 보기 위해 환경설정의 **협동 플레이 → 한 화면 협동**도 확인한다.
4. 기획서와 원본 음원은 `Docs/Design`과 `goblin-getaway/handoff`에 있다. 초기 기획과 현재 동작이 다르면 이 가이드의 웹 코드 경로부터 확인한다.

## 데이터와 좌표

- 시뮬레이션은 **30Hz** 고정 틱으로 둔다. 주행 거리(m), 갑판·지하층의 로컬 좌표, 화면 투영을 분리한다. 웹판은 화면에서 왼쪽으로 전진하고 Y가 아래로 증가한다. Unity Transform으로 변환할 때 Y 반전은 한 곳에서 적용한다.
- C# 상태와 규칙에서 이동·점유·소지품·충격·승객·구매를 함께 처리한다. 입력은 이동축, 조준축, 행동 시작·해제, 이탈, 소통 같은 명령을 보낸다. 카메라·HUD·소리는 상태와 이벤트를 읽는다. 충격과 이모티콘은 고유 ID로 한 번씩 재생한다.
- `Chapter` → `Stage` → `Wave`와 적 특성, 작업대, 업그레이드 카드는 Unity에서 수정 가능한 데이터로 옮긴다. ScriptableObject에 설정값을 두고 판마다 바뀌는 재고·거리·투표는 런타임 상태에 둔다. 웹판과 비교할 때 동일 시드와 동일 틱 입력으로 결과를 맞춰 본다.
- 모바일 가로형은 1920×1080 기준의 Canvas를 쓰고 안전 영역과 터치 범위를 실제 기기에서 검증한다. 온라인에서는 기기별 개인 카메라를 사용하고, 한 화면 2인은 작업 확대 또는 다른 층에 있을 때 시야를 나눈다.

## 현재 웹판을 Unity에 옮길 때

### 층과 작업대

| 층 | 배치와 동작 |
| --- | --- |
| 1층 | 마부석 한 개는 맨 왼쪽. 왕자·공주 좌석, 뒤쪽의 포수석·장전대, **5시 구석** 포탄 적재칸. |
| 지하층 | **3시** 포탄 더미, **9시 반** 음식 제작대, **12시** 바퀴 보관함, 고장 난 모서리의 수리 자리. 화면에는 어두운 실내가 보이고 외부 도로·추격대는 가려진다. |
| 양쪽 6시 반 | 같은 갑판 좌표의 계단. 한 번 건너면 계단 밖으로 나왔다가 다시 밟아야 반대로 이동한다. 포탄과 간식은 층간 운반 가능하다. |

작업 범위에 들어가면 자동 점유한다. 사람은 봇보다 우선하며 한 작업대에는 한 명만 머무른다. 이탈하면 이동과 개인 시야가 복귀하고, 작업대 바깥을 밟아야 재진입한다. 바퀴는 보관함에서 가져와 **바퀴 끼우기 → 차축 핀 고정**을 완료한다. 웹 좌표 속도는 기본 165, 예비 바퀴 소지 110, 포탄 소지 50이다. 포탄 운반 장구는 포탄 이동 속도에 적용한다. 바퀴 이탈 중 목표 주행 속도는 57%다.

### 입력·HUD·소통

- 터치는 화면 왼쪽 절반에서 누른 위치를 중심으로 가상 스틱을 띄운다. 평소 이동, 마부석·포수석 점유 중에는 조준, 장전 등 다른 점유 작업 중에는 스틱을 대기시킨다. 오른쪽 행동 버튼의 동작은 현재 작업에 따라 탭, 연타 또는 홀드로 바뀐다. 점유 중에는 이탈 버튼을 표시한다.
- P1은 WASD·Space·Q, P2는 방향키·Enter·오른쪽 Shift, 게임패드는 왼쪽 스틱·A 또는 R2·B를 사용한다. PC에서 Esc로 작업대를 이탈한다. 두 작업대가 점유된 로컬 2인에서는 P1부터 이탈한다.
- 타이밍 작업의 바늘과 성공 구간을 캐릭터 둘레에, 필요한 행동 문구를 캐릭터 위에 놓는다. 상단 중앙은 마차 아이콘이 있는 거리 진행 바, 남은 거리, 현재 웨이브 수를 표시한다. 층수 및 다음 웨이브 예고는 HUD에서 생략한다.
- **이모티콘 버튼**은 행동 버튼 지름의 2/3이며, 바로 위의 중심에서 자기 지름만큼 왼쪽으로 옮긴 11시 방향이다. 7종 선택 메뉴와 숫자키 1–7을 유지한다. 포탄·장전·바퀴 수리·마차 조작·아이 돌봄 요청과 좋아요·놀람을 캐릭터 옆과 팀 화면 상단에 표시한다. 층이 달라도 팀 알림을 받는다. 한 화면 2인에서 P2의 목록을 연 상태라면 숫자키는 P2 선택으로 처리한다.
- 상단 우측의 환경설정은 88×88px, 작전 시작은 높이 84px 기준이다. 좁은 화면에서는 진행 바나 알림과 터치 영역이 겹치지 않는지 확인한다.  
근거 `public/controls.mjs`, `public/game.mjs`, `public/emotes.mjs`, `app/globals.css`

### 포수·마부·적의 위협

- 더미 17발, 적재 1발, 장전 1발로 시작한다. 장전된 포탄은 점화 후 **2.5초** 동안 흔들리는 에임을 조정하고 자동 발사한다. 현재 속도 1,750, 반지름 14는 웹 화면 단위다. 틱 사이의 이동 선분을 검사해 접촉한 적을 모두 관통하고, 같은 적은 한 번만 처리한다. 포신 강화는 시각 크기와 판정 폭에 함께 반영한다.
- 발사 반동은 마차 전체와 운반 작업에 전달한다. 운반자가 포탄을 놓칠 위기에는 **1.6초** 안에 타이밍을 맞춰 붙잡는다. 카메라 흔들림·먼지·음향은 충격 이벤트를 구독한다.
- 마부 시야는 최대 2배. 왼쪽 스틱이 오른말·왼말의 조준점을 움직인다. 엉덩이 연타는 가속을 더하고 **오른말을 치면 화면 위, 왼말을 치면 화면 아래**로 조향한다. 허리·목·머리를 맞히면 급격히 말을 듣지 않으며, 상처가 5개면 피로, 8개면 화남 상태가 된다. 상처와 방향 피드백을 조준 화면에 보여준다.
- 추격대는 오른쪽 화면 밖에서 접근한다. 일격 후 0.8초 후퇴하고 약 1.4초 동안 접근 속도를 40%로 낮춘 뒤 재공격한다. 통나무·바위·사슴은 앞에서 등장하고 200 단위의 조향 폭 중 약 30%를 위협하며 충돌 시 내구도와 속도에 영향을 준다.
- 투석기는 첫 6초에 한 개의 바위를 예고하고 이후 스테이지별 약 12–13초 간격으로 던진다. 그림자가 접근하고 1.1초에 착탄 좌표를 고정한 뒤, 발사 4.8초에 떨어진다. 가속으로 착탄 지점을 지나가거나 반대쪽으로 조향해 피한다. 바위와 경고의 시각 크기, 충격파와 다량의 먼지를 살린다. 웹판의 **착탄 경고 표시는 2배**, 충돌 판정 타원 반지름은 **35×24**다. 경고와 실제 판정의 차이는 플레이테스트에서 확인한다. 초기 의도인 기본 속도 대비 약 20% 가속 회피도 보정 테스트에 넣는다.  
근거 `public/sim.mjs`, `public/horse-targets.mjs`, `public/road-obstacles.mjs`, `public/scene.mjs`

### 왕자·공주와 스테이지 사이

- 두 아이의 관심과 배고픔은 별도 상태다. 관심 20 이하에서 자리를 뜨고 마차를 돌아다니며 통로를 막는다. 가까이 가면 상태를 확인할 수 있다. 행동으로 안아 자기 좌석에 돌려놓으면 관심이 회복되고 약 7초간 머문다. 배회 중에는 적재탄 버리기, 대포 발사, 말 재촉 같은 방해를 일으킬 수 있다.
- 큰 충격에 앉은 아이가 떨어질 수 있다. 웹 기본 확률은 대포 25%, 투석기 명중 52%, 장애물 충돌 34%이며 완충 강화가 낮춰 준다. 떨어지면 85% 확률로 놀라 울고, 울고 있는 경우 먼저 달랜다. 배고픔 70 이상에서도 울 수 있다.
- 지하 9시 반의 음식 제작대에서 행동을 약 3초 홀드한다. 같은 작업 중 마차가 심하게 흔들릴수록 진행이 크게 줄어든다. 1층의 자기 좌석에 앉은 아이에게 간식을 먹이면 배고픔이 55 감소한다.
- 현재는 1챕터, 3스테이지, 각각 **1,000m**다. 예시가 아닌 실제 웨이브 시간(초)은 1스테이지 `4/16/28/40/52`, 2스테이지 `4/15/26/37/48/59`, 3스테이지 `3/13/23/33/43/53/63`이다. 적은 기병·정찰병·근위병의 임시 편성이고 새 적 파일을 받을 때 데이터 교체가 필요하다. 거리는 매 틱 속도만큼 누적하며 목적지 도달이 클리어 조건이다. 최고 속도에서도 마지막 웨이브가 먼저 나오게 하려면 가능 업그레이드·가속을 포함한 가장 빠른 실측 완주보다 마지막 웨이브 시간을 앞당긴다.
- 스테이지 종료 때 아이별 착석률 60%, 평균 관심 40%를 점수화하고 울음 비중으로 최대 4점씩 감점한다. 마왕에게 돌봄·마차 피해·보급 중 한 항목을 보고한 뒤 애정 포인트(AP)로 수리 및 업그레이드 카드를 구매한다. 비용은 카드별 3–6 AP. **같은 카드**에 현재 사람 과반이 투표해야 하므로 1·2·3·4인일 때 각각 1·2·2·3표가 필요하다. 투표가 확정되면 AP를 한 번 차감하고 투표를 초기화한다.
- 다음 스테이지에는 현재 내구도, 이탈한 바퀴, 업그레이드, AP가 이어지고 해당 스테이지의 웨이브·포탄·아이 상태를 새로 시작한다. 최종 스테이지는 평가를 표시하고 챕터를 완료한다.  
근거 `public/campaign.mjs`, `public/sim.mjs`, `public/intermission.mjs`

### 협동과 온라인

웹 서버는 `app/api/room/route.js`에서 같은 시뮬레이션을 실행하고, 브라우저는 폴링·보간으로 화면을 갱신한다. 방번호는 3자리, 최대 4석, 빈자리는 봇이 채운다. 접속 유지에는 방 코드와 별도의 좌석 키가 쓰인다. 서버가 작업대 점유·재고·피격·아이 운반·투표를 확정하며, 방장이 떠나도 기존 진행 상태로 남은 참가자에게 넘긴다. Vercel은 Turso, 이전 Sites용 빌드는 D1 어댑터를 쓴다.

Unity에서 NGO를 선택하면 명령과 상태 스냅샷을 교환하는 얇은 계층부터 만든다. 2인 연결 실험에서 브라우저 지원 전송 방식과 재연결을 먼저 검증한다. 웹 방과의 호환을 원할 때에만 기존 HTTP 프로토콜과 같은 출처 호스팅 또는 CORS 구성을 검토한다. Unity 빌드나 클라이언트에는 DB 자격증명을 넣지 않는다.  
근거 `public/game.mjs`, `app/api/room/route.js`, `db/schema.ts`, `db/room-turso.mjs`, `drizzle/`

## 회귀 검증표

| 상황 | 통과 기준 |
| --- | --- |
| 대포 한 발에 적 3명 겹치기 | 세 명 모두 한 번씩 명중한다. 처음 두 발을 사용한 뒤에야 지하 보급부터 새 포탄을 올리는 전체 흐름을 검증할 수 있다. |
| 충격 중 인수인계 | 운반자는 붙잡기 성공 시 같은 포탄을 보존한다. 실패 시 한 발만 손실된다. 요리 진행은 충격 크기에 맞춰 감소한다. |
| 1층·지하 동시 접속 | 각자의 작업대와 카메라에 맞는 층만 보인다. 팀 요청은 모두에게 보이고 다른 플레이어의 스틱·행동 입력이 섞이지 않는다. |
| 아이 낙상과 배고픔 | 같은 충격 로그에서 과도하게 자주 떨어지지 않는지 시드별로 측정한다. 달래기→안기→재착석→급식 순서를 확인한다. 거리가 멀어지면 아이 상태 UI가 사라진다. |
| 클리어와 상점 | 남은 거리 0에서 클리어되고 웨이브 카운트는 실제 소환 횟수다. 최고속 주행에서도 최종 웨이브를 보게 시간표를 검사한다. 동시 투표·재전송에도 구매와 비용 차감은 한 번이다. |
| 4인 방·이탈·재접속 | 5번째 참가 거절, 빈 슬롯 봇 인계, 운반 상태 유지, 방장 승계, 유효하지 않은 이전 스테이지 명령 거절을 확인한다. |

## 동봉된 웹판 로컬 실행

Node.js 22.13 이상을 사용한다. ZIP 안의 `goblin-getaway` 폴더에서 실행한다.

```sh
npm ci --include=dev
node ./node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3000
```

브라우저에서 `http://127.0.0.1:3000`을 열면 1인·한 화면 2인을 시험할 수 있다. 온라인 방까지 확인하려면 개인 개발용 Turso DB를 준비하고 서버 환경에 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`을 설정한 뒤 `node ./scripts/migrate-rooms-vercel.mjs`를 한 번 실행한다. `node ./node_modules/next/dist/bin/next build`가 공개 배포와 같은 빌드 진입점이다.

ZIP에는 Unity 씬·설정, 웹 작업본, 기획·상세 명세, BGM 두 곡의 MP3·WAV·렌더 소스가 들어 있다. Unity의 Library, 웹 의존성·빌드 캐시, 사용자별 실행 상태와 운영 환경 변수는 각 환경에서 복원한다.
