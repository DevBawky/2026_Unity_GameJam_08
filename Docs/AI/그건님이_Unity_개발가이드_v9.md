## 데이터와 좌표

- 규칙은 **30Hz** 고정 틱에서 계산한다. 주행 거리(m), 갑판·지하층 로컬 좌표, 화면 투영을 분리한다. 웹판은 왼쪽으로 전진하고 Y가 아래로 증가한다. Unity Transform으로 변환할 때 Y 반전을 한곳에서 적용한다.
- 이동축·조준축·행동 시작과 해제·이탈·소통을 명령으로 보낸다. 카메라와 HUD는 상태를 읽고 소리와 충격은 이벤트 ID를 기준으로 한 번 재생한다.
- 챕터·스테이지·웨이브, 적 특성, 작업대·업그레이드는 ScriptableObject로 옮기고 재고·거리·투표는 판마다 독립적인 런타임 상태로 관리한다. 같은 시드와 틱 입력으로 웹판과 Unity판을 비교한다.
- 모바일 가로형 Canvas 기준 해상도는 1920×1080이다. 실제 기기의 안전 영역과 터치 범위를 본다. 온라인 개인 카메라와 로컬 2인 분할 카메라의 HUD 투영을 각각 검증한다.

## 입력·HUD·소통

- 터치 화면 왼쪽 절반에서 누른 곳을 중심으로 가상 조이스틱을 띄운다. 평소 이동, 마부석·포수석 점유 중 조준, 장전 같은 다른 점유 작업 중에는 대기다. 화면 오른쪽 행동 버튼은 현재 작업에 따라 탭·연타·홀드로 동작한다. 점유 중 화면에 이탈 버튼을 표시한다.
- P1은 WASD·Space·Q, P2는 방향키·Enter·오른쪽 Shift, 게임패드는 왼쪽 스틱·A 또는 R2·B를 쓴다. PC에서 Esc로 작업대를 이탈한다. 로컬 2인 모두 작업 중이면 P1부터 이탈한다.
- **작업 말풍선**은 이모티콘 팀 알림과 같은 스타일이다. “대포를 조준하고 점화하세요”처럼 지금 할 행동 한 줄을 각자의 캐릭터 위에 띄운다. 점화 때는 심지 시간, 요리·달래기·말 상태는 진행도를 추가한다. 캐릭터가 조준 화면 밖에 있으면 같은 플레이어 영역 안쪽에 말풍선을 놓는다. 타이밍 작업은 캐릭터 둘레의 바늘과 성공 구간을 사용한다.
- 상단 중앙에는 마차 아이콘이 있는 거리 진행 바, 남은 거리와 현재 웨이브가 표시된다. 층수와 다음 웨이브 예고는 기본 HUD 구성에서 제외한다.
- 이모티콘 버튼은 행동 버튼 지름의 2/3이며 행동 버튼의 11시 방향이다. 숫자키 1–7도 사용할 수 있다. 일곱 가지는 포탄·장전·바퀴 수리·마차 조작·아이 돌봄 요청, 좋아요와 놀람이다. 사용자의 캐릭터 옆에 아이콘을, 팀원 모두의 상단에 메시지를 띄운다. 한 화면 2인에서 P2 이모티콘 목록이 열리면 숫자키는 P2에 적용한다.
- 환경설정은 88×88px, 작전 시작은 높이 84px 기준이다. 좁은 화면에서 진행 바·팀 알림과 터치 영역의 겹침을 확인한다.

구현 파일은 `public/controls.mjs`, `public/game.mjs`, `public/workstation.mjs`, `public/emotes.mjs`, `app/page.tsx`, `app/globals.css`다.

## 포수·마부·추격대

- 더미 17발, 적재 1발, 장전 1발로 시작한다. 장전된 탄을 점화하면 **2.5초** 동안 흔들리는 조준을 조절한 뒤 자동 발사한다. 포탄 속도 1,750과 반지름 14는 웹 좌표 단위다. 틱 사이 이동 선분이 접촉한 적을 모두 관통하고 같은 적은 한 번 맞힌다. 포신 강화는 외형과 판정 폭에 함께 적용한다.
- 반동은 마차 전체와 포탄 운반자에게 전달된다. 운반 중 놓칠 위기에는 **1.6초** 안에 타이밍을 맞춰 붙잡는다. 카메라, 먼지, 소리는 충격 이벤트에 반응한다.
- 마부 시야는 최대 2배다. 말의 엉덩이를 조준해 연타하면 가속과 조향이 쌓인다. **오른말은 화면 위, 왼말은 화면 아래**로 튼다. 허리·목·머리에 맞으면 약 3초간 해당 말이 놀라 조작에 반응하지 않는다.
- 한 말의 엉덩이에 타격 **8회**가 누적되면 그쪽으로 **1.2초 폭주**한다. 웹 기준 횡이동은 초당 176단위고 기본 주행 속도의 18%가 추가된다. 이후 **4초 지침**에는 그 말의 가속이 사라지고 목표 주행 속도에 0.78배를 적용한다. 지침 동안 상처가 회복되고 정상으로 돌아온다. 폭주는 한 번에 한 마리에서 발동한다. HUD에 타격 수·폭주·회복 상태를 표시한다.
- 추격대는 화면 오른쪽 바깥에서 접근한다. 일격 후 0.8초 후퇴하고 약 1.4초간 접근 속도를 40%로 낮춘 뒤 재공격한다. 기병의 말은 마차 말과 같은 그리기 배율인 1.58을 사용한다. 기병 말 몸통 판정을 외형에 맞추고 공격 지점은 창 길이에 맞춘다.
- 통나무·바위·사슴은 앞에서 나타나고, 200단위의 조향 폭 중 약 30%를 가로막는다. 충돌하면 종류에 맞는 피해와 감속이 생긴다.
- **빠진 바퀴**는 마차 뒤로 굴러가고, 경로에 걸린 기병을 날려 보낸다. 길가 나무·통나무·바위에 부딪히면 방향이 바뀌고 화면 뒤편으로 멀어지면 제거한다. 틱 사이 바퀴와 기병의 상대 이동을 판정한다. 지하에서 예비 바퀴로 수리하는 흐름은 굴러가는 바퀴와 독립적이다.
- 투석기는 시작 후 6초에 첫 바위를 예고하고 이후 약 12–13초 간격으로 한 개씩 던진다. 그림자가 접근하고 발사 후 1.1초에 착탄 표시를 고정한 뒤 4.8초에 떨어진다. 가속으로 착탄 지점을 지나가거나 반대쪽으로 조향해 피한다. 경고 표시 지름은 2배이며 실제 판정 타원 반지름은 35×24다. 착탄 때 큰 바위, 지면 흔들림과 먼지를 보여준다.

구현 파일은 `public/sim.mjs`, `public/horse-targets.mjs`, `public/road-obstacles.mjs`, `public/scene.mjs`다.

## 왕자·공주와 스테이지 사이

- 아이별 관심과 배고픔을 계산한다. 관심 20 이하에서 자리를 뜨고 통로를 막을 수 있다. 가까이에서 상태가 나타난다. 돌아다니는 동안 적재탄 버리기, 대포 발사, 말 재촉을 할 수 있다.
- 앉은 아이는 대포 반동 25%, 투석기 명중 52%, 장애물 충돌 34%의 기본 확률로 떨어진다. 완충 강화는 이 확률을 낮춘다. 낙상 시 85% 확률로 놀라 운다.
- **안아 올리기 → 안고 걸어서 달래기 → 자기 좌석에서 행동해 앉히기** 순서다. 달래기는 실제 이동 거리를 누적한다. 웹 기준 312.5단위를 걸으면 완료되며 방해가 없는 직선에서 약 2.5초다. 멈춰 있거나 벽에 막혀 이동 거리가 0이면 유지된다. 재착석하면 관심이 차고 약 7초간 자리에 머문다. 배고픔 70 이상의 울음은 별도로 판단한다.
- 지하 9시 반 음식 제작대에서 행동을 약 3초 홀드한다. 흔들림이 클수록 작업 진행이 더 많이 감소한다. 1층 자기 좌석에 앉은 아이에게 간식을 먹이면 배고픔이 55 내려간다.
- 현재 1챕터 3스테이지, 각 목표 **1,000m**다. 웨이브 시간(초)은 스테이지 1 `4/16/28/40/52`, 스테이지 2 `4/15/26/37/48/59`, 스테이지 3 `3/13/23/33/43/53/63`이다. 기병·정찰병·근위병이 편성된다. 거리를 매 틱 누적하고 목적지 도달 시 클리어한다. 마지막 웨이브를 모든 판에서 보이게 하려면 가능한 강화·가속을 포함한 최단 완주 시간보다 웨이브 시각을 앞당긴다.
- 스테이지 종료 때 아이별 착석률 60%, 평균 관심 40%를 점수화하고 울음 비중에 따라 최대 4점씩 감점한다. 마왕에게 돌봄·마차 피해·보급 중 한 항목을 보고한 뒤 AP로 수리·업그레이드 카드를 구매한다. 비용은 3–6 AP, 같은 카드에 사람 과반수인 1·2·3·4인 기준 1·2·2·3표가 필요하다. 과반이 되면 AP를 한 번 차감하고 표를 초기화한다.
- 다음 스테이지에는 내구도·이탈 바퀴·업그레이드·AP가 이어지고 새 웨이브·재고·아이 상태를 시작한다. 마지막에는 평가를 표시하고 챕터를 완료한다.

구현 파일은 `public/campaign.mjs`, `public/sim.mjs`, `public/workstation.mjs`, `public/intermission.mjs`다.

## 무한 테스트 모드

로컬 1인과 한 화면 협동의 시작 대기 화면에서 **작전 시작** 왼쪽의 **테스트 모드**를 누른다. 목적지를 지나도 주행을 이어가고, 피해가 누적돼도 내구도는 최소 1을 유지한다. 스테이지 웨이브가 반복되고 지하 포탄 더미가 비면 보충된다. 웨이브 생성 시 오래된 적을 정리하고, 첫 일격을 가한 추격대는 14초 후 퇴장한다. HUD는 누적 주행 거리와 웨이브 수를 표시한다. **환경설정 → 테스트 종료**를 누르면 시작 대기로 돌아온다.

Unity판에서도 테스트·일반 모드가 같은 작업과 충격 판정을 사용하게 한다. 구현 파일은 `public/sim.mjs`, `public/game.mjs`, `app/page.tsx`다.

## 협동과 온라인

최대 네 자리, 3자리 방번호, 비어 있는 자리는 봇이 맡는다. 서버는 점유·재고·피격·아이 운반·투표를 확정하며 진행 중 합류와 이탈 시 캐릭터 상태를 넘긴다. 방장이 떠나면 남은 참가자에게 권한이 넘어간다. 웹 서버는 `app/api/room/route.js`에서 같은 시뮬레이션을 실행하고 클라이언트는 폴링 스냅샷과 예측으로 화면을 갱신한다. Vercel은 Turso, 이전 Sites 배포는 D1 어댑터를 사용한다.

Unity에서 NGO를 선택하면 명령과 상태 스냅샷을 교환하는 계층부터 만든다. 브라우저 두 개로 연결과 재연결을 검증한 뒤 네 자리, 봇 인계와 동시 투표를 확인한다. 기존 웹 방과 연결하려면 웹 HTTP 메시지 규칙과 배포 출처를 맞춘다. DB 자격증명은 서버 환경에 둔다.

## 동봉된 웹판 로컬 실행

Node.js 22.13 이상을 사용한다. ZIP 안 `goblin-getaway` 폴더에서 실행한다.

```sh
npm ci --include=dev
node ./node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3000
```

`http://127.0.0.1:3000`에서 1인과 한 화면 2인을 시험한다. 온라인 방은 개발용 Turso DB와 서버 환경의 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`이 필요하다. 변수를 설정한 후 `node ./scripts/migrate-rooms-vercel.mjs`를 한 번 실행한다. Vercel과 같은 진입점으로 빌드하려면 `node ./node_modules/next/dist/bin/next build`를 실행한다.

ZIP에는 Unity 씬과 설정, 웹 소스, 기획과 상세 명세, BGM 두 곡의 MP3·WAV·렌더 소스가 들어 있다. Unity Library와 웹 의존성은 각 환경에서 복원한다.
