# 《그건 님이!!!》 Unity 개발 가이드 · v12

2026-11-19 · Unity `6000.3.28f1` · 웹판 `cavalry-depth101`

이 가이드는 웹판의 마차, 대포, 기병과 HUD 변경을 기존 Unity 프로젝트에 옮길 때 사용한다. 편집 ZIP에는 `MJ` 브랜치 커밋 `73101bc` 위의 최신 웹 소스 및 에셋과 기존 Unity 프로젝트를 함께 담았다. 웹판은 프로덕션 빌드와 플레이테스트 6개를 통과했다. 최신 웹 기능의 Unity 이식과 에디터 플레이 검증은 후속 작업이다.

## 프로젝트 열기

1. `그건님이_전체편집프로젝트_v12.zip`을 풀고 `Assets`, `Packages`, `ProjectSettings`가 있는 폴더를 Unity Hub에 추가한다. `6000.3.28f1`로 연다. 기존 URP `17.3.0`의 Renderer2D, Input System `1.20.1`, uGUI `2.0.0`, Netcode for GameObjects `2.14.0`, Unity Transport `2.7.5`를 사용한다.
2. 활성 씬 순서는 `Assets/Scenes/Lobby.unity` → `Assets/Scenes/mainGame.unity`다. `Lobby`에서 호스트와 클라이언트를 연결하고 `mainGame`에서 `Assets/Prefabs/Cart.prefab`과 플레이어, 적, HUD 연결을 확인한다.
3. `Assets/Scripts/Cart/CartStations.cs`, `Assets/Resources/CartRules.asset`, `CartNetworkState`에서 현재 권한과 작업 상태를 확인한다. 카메라 및 층 전환은 ZIP의 `Docs/AI/그건님이_Unity_개발가이드_v11.md`도 참고한다. 활성 씬과 변경된 상호작용은 v12를 기준으로 한다.
4. 웹 비교는 Node.js `22.13.0` 이상으로 `goblin-getaway/`에서 `npm ci --include=dev`를 실행한 뒤 `node ./node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3000`을 실행한다. 브라우저에서 `http://127.0.0.1:3000`을 열고 솔로 또는 테스트 모드로 시작한다.

ZIP의 `Handoff/v12/원본/`에는 견인마 원본 시트와 왕족 제작 원본을 담았다. `Handoff/v12/검증화면/`의 웹 캡처로 완성 화면을 비교할 수 있다. 기획·상세 명세는 `Docs/` 및 `goblin-getaway/handoff/`, 발표용 음악의 WAV·MP3와 편곡·렌더 소스는 `goblin-getaway/handoff/music/`에 있다.

## 이식 순서

1. `Cart.prefab`에 갑판, 왕족, 조종석, 견인마 프레임을 연결하고 갑판과 도로에서 쓸 좌표 기준을 정한다.
2. 대포 작업대와 적재함을 옮긴다. 포탄 적재 → 장전 → 점화 → 조준 → 발사와 바퀴 수리를 호스트·클라이언트에서 각각 확인한다.
3. 기병 프리팹에 달리기, 창, 발굽 그림자를 연결하고 겹칠 때 앞뒤 순서를 검증한다.
4. 조준 안내를 이모티콘 노티와 같은 규격으로 연결한다. 좁은 가로 화면과 세로 화면에서도 조작을 가리지 않는지 확인한다.

- 새 픽셀 스프라이트는 Point 필터, 알파 사용, 압축 None, Full Rect로 시작한다. 각 시트 안에서 같은 피벗을 사용한다. 웹 좌상단 기준의 자르기 영역을 Unity Sprite Editor로 옮길 때 Y는 이미지 높이 − 원본 Y − 잘라낸 높이로 계산한다.
- 웹은 오른쪽 X와 아래쪽 Y가 양수이고 시뮬레이션은 초당 30틱이다. 아래 Unity 좌표는 웹 `(527.5, 0)`을 마차 로컬 원점으로 잡고, 100웹 단위를 Unity 1단위로 환산한 예시다. 기존 Unity 씬에서는 `CartStations.WorldPerWebUnit`이 `cartBody.bounds.size.x / 331f`를 사용한다. 폭 375인 새 갑판 스프라이트와 기존 작업 반경·충돌의 월드 크기를 대조해 일관된 환산값을 적용한다. 도로 소팅은 동일 지면 기준으로 맞추고 애니메이션 시작과 경과는 서버 시각을 사용한다.
- 셀 내부의 웹 앵커가 `(ax, ay)`이면 정규화 피벗은 `(ax / w, 1 − ay / h)`다.
- 월드 스프라이트는 씬 또는 프리팹에 저장한 SpriteRenderer로 구성한다. HUD, 버튼, 상호작용 UI는 씬 또는 프리팹에 배치한다. 이미지에는 실제 PNG와 기본 Image, 텍스트에는 TMP_Text와 에디터에서 연결한 폰트 에셋을 쓴다. 런타임은 직렬화된 UI의 값, 색상, 위치와 표시 상태를 갱신한다.

### 플레이어와 왕족

- 플레이어 1–4는 순서대로 bottom_purple, bottom_orange, bottom_blue, bottom_pink의 1–4번 PNG를 사용한다. 원본은 왼쪽을 향한다. 충돌 해결 뒤 실제 X 이동이 오른쪽이면 SpriteRenderer.flipX를 켜고 왼쪽이면 끈다. 정지, 수직 이동, 조준 중에는 마지막 방향을 유지한다. 장비와 손에 들린 왕족 위치도 반전한다. 이름표, 외곽 표시, 충돌 판정은 별도 오브젝트로 유지한다. 웹 이동은 4틱당 1프레임, 대기는 13틱당 1프레임이며 플레이어 위상은 0·3·6·9틱이다.
- royal-children.png는 144×88, 36×44 셀 4열 × 2행이다. 위 왕자, 아래 공주이며 왼쪽부터 앉기·서기·울기·심심함이다. 좌석은 왕자 `(−0.175, 0.74)`, 공주 `(0.215, 0.74)`다. 앉은 스프라이트는 좌석에서 위로 15웹픽셀, 스케일 1.42다. 기존 안기, 떨어짐, 복귀에 새 포즈를 연결하고 같은 층의 .52유닛 안에 있는 플레이어에게 상태를 표시한다.

### 오른쪽 포탄 더미

- 장판 중심은 웹 (648,56)의 bottom_bombbox다. 실물 더미는 그 오른쪽 웹 (685,56), Unity 로컬 `(1.575, −0.56)`에 둔다. 보관함 시각 크기는 34×21웹픽셀이다. 좁은 화면에서 더미를 담는 웹 카메라 여유 폭은 +112픽셀이다.
- rack-shell.png를 12웹픽셀 너비 기준으로 최대 5개, 아래 3개와 위 2개로 쌓는다. 더미 중심을 기준으로 아래 세 칸의 웹 오프셋은 (−9,+5), (0,+5), (+9,+5), 위 두 칸은 (−4.5,−3), (+4.5,−3)이다. 실제 수량은 TMP_Text로 표시하고 0에서는 포탄 이미지를 전부 숨긴다. 기존 Unity storedShell 1개 토글을 미리 배치한 SpriteRenderer 5개의 표시 상태로 확장하고 rackCountLabel을 연결한다.

### 바퀴 수리 애니메이션

- 위쪽 bottom_wheel_topequip1–4와 아래쪽 bottom_wheel_bottomequip1–4를 위치별로 연결한다. 첫 장착 성공 시각과 장착 슬롯을 핀 고정과 별도로 기록한다.
- 2틱당 1프레임을 0.85배 속도로 재생한다. 장착 뒤 0–9틱의 시각 프레임은 1,1,1,2,2,3,3,3,4,4다. 10틱부터 일반 바퀴로 돌아온다. 장착 8틱 뒤에 플레이어가 핀 고정에 성공하는 경우에도 장착 애니메이션을 완주한다. 재시작과 스테이지 전환에서 시각과 슬롯을 초기화한다. 이전 상태의 장착 인덱스는 수리 진행값과 파손 슬롯으로 유도한다.
- 장착 중 같은 위치의 먼지 효과는 숨긴다. 모션 감소 설정은 장착 오버레이를 생략한다. 기존 CartRules와 LooseWheels의 수리 판정과 보상은 그대로 사용한다.

## 대포 발사와 안내

| 시점 | 포신 배율 |
| --- | --- |
| 발사 입력부터 2.5초 | 75틱에 걸쳐 조준하는 동안 포신이 맥동하며 점차 납작해진다. |
| 발사 직전 0.3초 | 66–74틱에 가로 맥동이 1.15배 빨라진다. 74틱에서 가로 약 114.7%, 세로 약 84.3%다. |
| 발사 순간 | 가로 100%, 세로 108%. 마차 연결부를 피벗으로 사용한다. |
| 발사 후 0.4초 | 12틱에 걸쳐 세로 100%로 감쇠 복귀한다. 가로는 100%다. |

- public/scene.mjs의 cannonBarrelScale을 기준으로 구현한다. 발사 경과틱/12를 p로 두면 복귀 세로 배율은 1 + .08 × (1−p)² × cos(2πp)이며 12틱부터 정확히 1이다.
- CartStations의 cannonVisual, cannonMuzzle 및 FuseDeadline을 사용한다. 연결 피벗은 웹 (704,0), Unity 로컬 `(1.765, 0)`이고 포신 길이는 .44유닛이다. 받침대와 포신을 별도로 두고 조준 회전이 적용된 포신 로컬 축을 스케일한다. 섬광과 조준선은 같은 시각 포구를 따른다. 호스트 발사 틱과 Projectile 판정은 기존 상태를 사용한다. 발사 뒤 조준 카메라 60틱 유지와 15틱 복귀를 검증한다.
- 조준 안내는 `Assets/Prefabs/Emote/Canvas Emote UI.prefab`의 `Panel | Emote Notice`와 상단 중앙 앵커 및 카드 규격을 맞춘다. 기존 `Canvas HUD.prefab`과 `Canvas InGame.prefab`의 계층과 `TeamEmotes.cs`, `WorkGuide.cs`, `PlayerWorkHud.cs`를 확인한다. 조준 안내 제목, 조준률 `Image` 채움과 수치, 남은 시간은 에디터에서 연결한다. 안내의 `Raycast Target`을 끈다.
- 단독일 때 같은 위치에 놓고 둘이 보일 때 조준이 위, 이모티콘이 아래다. 카드 높이는 화면 짧은 변의 11%를 66–88웹픽셀로 제한한다. 상단은 화면의 22%에서 높이만큼 올리고 캠페인·안전 영역 아래에서 시작한다. 좁은 가로 화면은 기존 이모티콘 열 분할과 안전 영역을 적용한다. app/globals.css의 .top-notices와 app/page.tsx를 참고한다. 1280×720에서 단독 카드 760×79.2, 390×740에서 370×66, 동시 배치되는 568×320 소형 가로 화면의 카드별 266×66웹픽셀을 비교 기준으로 사용한다.

## 기병 달리기, 창, 그림자, Y 정렬

- cavalry-run.png는 1600×184, 200×184의 8프레임이다. 초당 16프레임에 적 ID별 위상을 더한다. 웹 셀 기준점은 (106,114), 월드 표시 배율은 .44다. Unity 정규화 피벗은 (106/200, 1−114/184)이며 PPU 100에서 스케일 .44다. 피격·폭발 사망 시트는 각각 2틱당 1프레임을 재생하고 30틱까지 마지막 프레임을 유지한다.
- Enemy_Lancer에 말·병사와 손 피벗을 연결한다. enemy_spear.png의 (0,28,85,13) 영역을 사용한다. 원본이 왼쪽을 향하고 손은 잘라낸 이미지 X49에 있다. 1.25배 기준 손에서 창끝까지 61.25웹픽셀이다. 말·병사 시각 원점은 적 X+40, Y이며 그 원점에서 손 오프셋은 웹 (−10,−3)이다.
- 호스트가 strikeTarget 피해 위치를 기록하는 틱에 창끝이 그 위치에 닿게 한다. 0–3틱 찌른 자세를 유지하고 3–12틱 smoothstep으로 돌아온다. 몸이 이동하는 가로 비율은 .65의 1.30배인 .845, 세로 비율은 .65다. 남은 차이를 손과 창에 주어 같은 표적에 닿게 한다. 창 이동은 한 번의 서버 피해에 연결한다.
- 웹 슬롯별 접근 X는 750, 750, 773, 783, 783이며 Y는 −86, 86, 0, −43, 43이다. 각 피해 목표 X는 692, 692, 715, 715, 715다. Enemy.cs의 서버 공격 및 애니메이션 동기화 흐름에서 관리한다.
- 달리는 동안 그림자는 몸과 같은 프레임으로 [발굽 앞 X, 뒤 X, 바닥 Y]를 선택한다. X 중심은 두 발굽 X의 평균, Y는 시트 상단에서 바닥 Y−1픽셀을 적용한 위치다. 가로 반경은 두 X 차이의 절반에 월드 스프라이트 배율을 적용하고 4웹픽셀을 더한다. 견인마는 깊이 8, 기병은 4.5웹픽셀의 두 겹 타원을 사용한다. 도약과 사망 중 그림자는 지면 기준을 유지한다. 바퀴에 맞아 뜨면 달리기 인덱스 0, 대포 사망은 인덱스 4의 발굽 위치를 사용한다.
- 견인마 8프레임 범위는 [30,84,77], [29,87,82], [23,101,83], [20,103,82], [14,101,82], [19,105,82], [39,87,81], [39,87,81]이다.
- 기병 8프레임 범위는 [62,136,172], [49,131,175], [41,156,175], [41,156,175], [35,155,178], [37,174,177], [64,154,177], [64,154,177]이다.
- 그림자, 말·병사, 창을 한 SortingGroup에 넣고 그룹 내부 순서를 그림자 → 말·병사 → 창으로 둔다. 그룹끼리는 찌르기 몸 오프셋을 포함한 지면 기준 월드 Y가 낮을수록 높은 sortingOrder를 받는다. 월드 Y가 같으면 X가 큰 기병을 먼저 그리고, 같은 깊이의 탑승자나 플레이어는 기병 위에 그린다. 같은 지면 앵커를 공유해 창끝과 몸의 흔들림이 좌우 병사 사이에 순서를 바꾸지 않게 한다.
